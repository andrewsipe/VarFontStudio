Instancer v2 — fvar-first, static-only edits

Changes from v1, based on the naming-mode and scope discussion:

  • Removed the STAT / fvar-hybrid / raw toggle. fvar is the resolved name whenever it's usable; STAT is a silent fallback, only surfaced when it's actually in use.
  • Removed the summary card row — counts now live only on the filter badges, no duplicated numbers.
  • "Style" is now a real RIBBI fold (Regular/Italic/Bold/Bold Italic from the bold+italic bits), not a copy of the STAT string.
  • Added a PostScript Prefix control (inferred via the same ID25 → ID6 stem → ID16/1 chain as the main app) with an inline override — this is a static-file-only cleanup, so it lives here instead of requiring a trip back to Studio.
  • Duplicate-output rows and fvar-incomplete rows can be resolved with an inline name override scoped only to that static file. Duplicate status recomputes live off the resolved name — including overrides — so fixing one row's name can clear the flag on both rows.
  • Fallback rows also get a "Fix in Studio" link, since a font arriving with incomplete fvar naming across many instances is a naming-order problem, not a one-file problem — Instancer doesn't try to out-guess Studio's naming policy.
  • Collision detection is now three-shaped, not one: "collision" (different coordinates, same output name — a plain filename clash), "identical" (same coordinates, different name — two files that would be pixel-for-pixel the same design wearing different names; the more deceptive case, and one the old name-only check missed entirely), and "exact" (same coordinates and same name — plain duplication). All three now block Generate when present in the current selection, rather than only being visible if someone happens to notice the row highlight.
  • Add Instance now blocks on a matching coordinate before the row is created, rather than adding it and hoping the resulting flag gets noticed — the common case is the instance already being in the list and going unnoticed, not an intentional second file at the same point in the design space.
  • Custom rows are fully live-editable (name, every axis, bold/italic), not just name-with-a-revert like source rows. They have no original value in the source font to protect or revert to — the "override/revert" framing only makes sense for a row that came from somewhere; a custom row's current state simply *is* its state. Bold/Italic are now explicit checkboxes at creation instead of guessed from the typed name.
  • "Will fail" is now a distinct tier from the amber fallback. If there's no STAT value to fall back to either, fontTools' instancer doesn't just produce an imperfect name — it raises (the `updateFontNames` ValueError case). That's a pre-flight-detectable write failure, not a naming preference, so it gets the same red treatment as a real collision and blocks Generate the same way, rather than only surfacing after a failed write.
  • Generate now defaults to a fresh per-batch subfolder instead of writing straight into the chosen folder, so re-running Generate after a naming tweak can't silently overwrite a prior run's output — the folder-collision case a same-batch dedup check can't see, since it only knows about the current session. The checkbox lets someone opt back into a stable path on purpose (e.g. if something downstream expects one), with an explicit warning that doing so means filename collisions there will overwrite.
